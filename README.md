# 云程旅行 · 航空旅行一站式服务平台

以携程公开首页为逆向分析对象，使用 **REA 6.4.0** 留存公开页面、脚本、网络和静态分析证据，再独立实现一个可本地运行的航空旅行课程项目。

**进入项目后运行 `npm start`，访问 <http://127.0.0.1:4173/>。项目运行不需要安装第三方依赖。**

```powershell
Set-Location L:\rea\rexiecheng
npm start
```

建议使用 `.nvmrc` 的 Node 24.18.0 和 `packageManager` 的 npm 11.16.0。运行要求为 Node ≥24；本次实际验证环境为 Windows x64、Node 24.14.0、npm 11.9.0，未安装或升级工具链。Node 24 的内置 SQLite 可能显示 ExperimentalWarning，不影响本次已验证功能。

## 已实现

- 国内单程航班：8 个城市、56 个方向组合、按日期生成 5 个模拟航班；搜索、日期低价栏、航空公司与预算筛选、舱位、人数和多种排序。
- 智能推荐：可解释规则评分，综合票价、时长与早晚出发惩罚；动态模拟价格每 5 分钟更新，报价锁定 10 分钟。
- 预订：1–6 位虚构旅客，后端报价核验、余票原子扣减、创建幂等、15 分钟支付时限。
- 订单：列表与筛选、状态时间线、模拟支付成功/失败、出票、取消与模拟退款、过期释放库存。
- 在线值机：单人已出票订单、起飞前 48 小时至 45 分钟窗口、30 排 A–F 选座、座位冲突校验、模拟登机牌与行程文本下载。
- 酒店、门票：本地精选目录与城市筛选，联动行程规划。它们提供查询和规划，尚未实现独立酒店/门票交易。
- 行程规划：1–7 日计划、住宿/门票/餐饮交通预算估算、保存、历史查看、文本下载。
- 多角色：旅客与旅行社演示身份；订单与行程按角色隔离，旅行社查看代订订单数、出票金额、待支付数和出行人数。
- 响应式界面：桌面侧边导航、移动底部导航、原生模态弹窗、错误提示、加载反馈、键盘焦点与减少动画偏好。

## 五分钟演示

1. 首页默认查询“上海 → 北京，明天”，点击任意“预订”。
2. 点击“填入演示信息”，使用虚构姓名、证件号与手机号创建订单。
3. 可先点“模拟支付失败”，再点“模拟支付”，查看出票后的事件记录。
4. 点击“在线值机”，在开放时间内为单人订单选择座位，确认后查看模拟登机牌。
5. “我的订单”查看历史；“精选酒店 / 门票·活动”点击“规划住宿 / 规划游玩”，生成并保存行程。
6. 右上角身份按钮可切换到旅行社，再进入“旅行社工作台”。

所有价格、库存、评分、交易、PNR 和登机牌均为本地模拟数据。演示身份无需密码，所有浏览器的同一角色共享示例账户；请仅填入虚构信息。它不是生产身份认证或真实出票系统。

## 检查

```powershell
npm test
npm run test:performance
npm run verify:evidence
```

`npm test` 使用临时 SQLite 与真实本地 HTTP 请求；性能测试启动独立临时服务。`verify:evidence` 检查现有 Evidence 文件、截图/资源摘要、脚本导出校验和本地场景里程碑，不会访问原站。

REA 场景输入在 `inputs/`；使用已安装 Chrome。`scripts/run-rea.ps1` 可重跑本地场景并使用新的独立数据库，输出到带时间戳的目录，保留已有证据。原站需要网络，本地业务不依赖原站或第三方 CDN。

## 项目结构

```text
frontend/            浏览器 ES Modules、CSS、HTML、原创 SVG 插画
backend/catalog.mjs  模拟城市、航班时刻、酒店与门票目录
backend/service.mjs  报价、推荐、订单状态与行程规则
backend/store.mjs    SQLite 表、事务与事件记录
backend/server.mjs   HTTP API、演示会话与静态资源入口
tests/               HTTP 业务测试与 SQLite 持久化测试
scripts/             性能测量、REA 采集提取和证据核验
inputs/              可复查的 REA 场景与视图输入
reports/             设计、API、逆向、验证报告
data/                自动生成的本地 SQLite，已忽略
```

`PORT`、`HOST`、`TRAVEL_DB` 可配置。默认只监听回环地址。停止使用 Ctrl+C；再次启动会读取已有本地订单。需要空白演示时，把 `TRAVEL_DB` 指向一个新的文件即可，无需删除已有数据。

## 外部服务集成范围

支付与航信目前使用同步本地模拟适配器，未调用携程私有接口。设计文档给出了未来替换成异步网关时所需的支付意图、回调验签、幂等和补偿方案。生产登录、真实支付、真实库存、多人逐人值机、酒店/门票交易、往返/中转/国际航班和真实地图路径规划未实现。
